ความเป็นเจ้าของข้อมูล ข้อมูลผูกกับบัญชี Google ส่วนบุคคล ข้อมูลจะอยู่ภายใต้ความปลอดภัยของบัญชีสถาบันและไม่ถูกนำไปเผยแพร่หรือฝึกโมเดล
ถิ่นที่อยู่ของข้อมูล (Data Residency) ผู้ใช้ไม่สามารถระบุภูมิภาคได้ จัดเก็บข้อมูลภายใต้ระบบ Workspace for Education ของโดเมนโรงเรียน
ประเภทไฟล์ที่รองรับ Google Docs, Slides, PDF, TXT, Markdown, Audio, Image, YouTube, Web URL รองรับเหมือนเวอร์ชันปกติ แต่เพิ่มไฟล์ Microsoft Office (.docx, .pptx, .xlsx)
การยืนยันตัวตน (Authentication) ใช้บัญชี Google ส่วนตัว (Gmail) รองรับ SSO, Cloud Identity, และผู้ให้บริการภายนอก (Third-party IdP) เช่น Okta, Entra ID
การแชร์ (Sharing) สามารถสร้าง Public Link หรือแชร์ผ่านอีเมลให้ใครก็ได้ ควบคุมขอบเขตการแชร์เฉพาะนักการศึกษาหรือกลุ่มเพื่อนร่วมชั้นเรียนในโดเมนเดียวกัน
การจัดการสิทธิ์ (Roles) เป็นเจ้าของโน้ตบุ๊กส่วนตัว ระบบควบคุมการแชร์และกำหนดสิทธิ์ผู้ดู/ผู้อ่านในโดเมนการศึกษา
ความปลอดภัย (Security) ไม่มีมาตรฐาน VPC-SC รองรับมาตรฐาน VPC Service Controls (VPC-SC) เพื่อป้องกันข้อมูลรั่วไหล
URL การเข้าใช้งาน notebooklm.google.com เข้าถึงผ่านเว็บบัญชีการศึกษาเพื่อความปลอดภัยในการคุ้มครองข้อมูล

2. โควต้าและขีดจำกัดด้านระบบทั่วไป

ในระดับโครงสร้างพื้นฐาน Gemini Enterprise ใช้โควต้าร่วมกับ Discovery Engine API และ Vertex AI Search

Allocation Quotas:

  • Data Stores: จำกัดที่ 100 แห่งต่อโปรเจกต์ (ขอขยายเป็น 500 ได้)
  • Engines: จำกัดที่ 150 ตัวต่อโปรเจกต์
  • Documents: รองรับได้สูงสุด 10,000,000 เอกสารต่อภูมิภาคในหนึ่งโปรเจกต์

Rate Quotas:

  • LLM Query Requests: 60 ครั้งต่อนาทีต่อโปรเจกต์
  • Conversational Search: 300 ครั้งต่อนาทีต่อโปรเจกต์
  • Document Read/Write: อ่าน 300 ครั้ง/นาที, เขียน 12,000 ครั้ง/นาที

3. ขีดจำกัดสำหรับ NotebookLM การศึกษา

  • จำนวนโน้ตบุ๊ก: สูงสุด 500 เล่มต่อผู้ใช้
  • แหล่งข้อมูล (Sources): สูงสุด 300 แหล่งต่อโน้ตบุ๊ก
  • ขนาดแหล่งข้อมูล: สูงสุด 200 MB หรือ 500,000 คำต่อแหล่งข้อมูล
  • Queries (การถามตอบ): 500 ครั้งต่อโน้ตบุ๊กต่อวัน
  • Audio Overviews: สร้างได้ 20 ครั้งต่อโน้ตบุ๊กต่อวัน

ความปลอดภัยและการควบคุมของสถาบัน

ส่งเสริมการใช้ AI ในโดเมนโรงเรียนได้อย่างปลอดภัย ด้วยระบบการดูแลและควบคุมสิทธิ์ใช้งานจากส่วนกลาง

  • ช่วยตอบสนองความต้องการด้านความปลอดภัยและความเป็นส่วนตัวของคุณด้วยมาตรการรักษาความปลอดภัยในตัว

  • ควบคุมการเปิด/ปิดสิทธิ์การใช้งานของแอป Gemini ให้เหมาะสมกับระดับชั้นเรียนและผู้ใช้งานอายุน้อย

  • ระบบคัดกรองความปลอดภัย (Model Armor) ป้องกันเนื้อหาที่ไม่เหมาะสมและการโต้ตอบที่เป็นอันตรายในเชิงรุก

  • ใช้เครื่องมือค้นหาบทสนทนา Google Vault เพื่อควบคุมความโปร่งใสและสร้างรายงานการใช้งานภาพรวมของสถาบัน

  • มาตรฐานความปลอดภัยระดับสากลสอดคล้องกับระเบียบกฎหมายความปลอดภัยข้อมูลเยาวชน เช่น COPPA และ FERPA

*ผู้ดูแลระบบสามารถจัดการทุกอย่างได้จากคอนโซลแอดมิน Workspace
